# 交接协议（dispatch / receipt）

> 哨兵只负责"发现变化"。**双方对文件名和字段有共同约定，才谈得上"看懂"。**
> 这份约定是通用的，可按项目改名（`patrol.mjs --dispatch-re` / `--receipt` 可覆盖默认值）。

## 0. 一条总原则

共享面只有一个目录。**谁都不许越目录写盘**——越界的写入是两个代理互相污染的唯一途径。
派单里应当写明本单允许写的文件白名单（通常就是"一个回执 + 可选证据文件"）。

## 1. 目录与命名

```
handoff/
├── <task-id>-dispatch-<slug>.md     # 派单（派单方写）
├── <task-id>-receipt.md             # 回执（承接方写）
└── <task-id>-evidence-*.{md,txt}    # 可选：中间证据件（承接方写）
```

- `task-id` 建议形如 `task-001` / `job-7`：**短、唯一、可排序**。
- 一个 task-id 只允许一份派单、一份回执。
- 重新派同一件事要换新 task-id（`-v2`），**不要原地改写历史件**。

## 2. 派单（dispatch）必含

```markdown
# <task-id>-dispatch · 一句话任务名

> 派单方：<A>　　承接方：<B>
> 授权依据：<谁在什么时候授权了什么>
> 效力口径：本单只允许 <范围>

## 0. 硬边界
1. 只允许写 <这个目录> 内的这些新文件：<回执>、<证据件命名前缀>
2. 不修改目录内任何既有文件
3. 不做 <明确排除的事>（安装/下载/生产/打包/合入…）
4. 能力不足的项如实标 `UNABLE`，不得伪装通过
```

## 3. 回执（receipt）必含

```yaml
task_id: <task-id>
executor: <承接方标识>
model_id: <实际干活的模型名，如实填，不得冒名>
overall: <五态之一>
```

外加一张逐项结论表，每行必须有 **结论 + 证据 + SHA256**：

```markdown
| 项 | 结论 | 证据文件或摘录 | SHA256 |
|---|---|---|---|
| M1 | OK | <命令与输出摘要> | <证据件哈希> |
| T1 | AGREE | <原文对照> | <被引件哈希> |
```

### `overall` 五态（只能用这五个）

| 值 | 含义 |
|---|---|
| `已完成` / `done` | 本单范围内的事项确实做完并验过 |
| `模板` / `template` | 交的是空白模板/表格，**不是执行结果** |
| `未验证` / `unverified` | 交付了但没独立验过 |
| `阻断` / `blocked` | 卡在外部前置上，附阻断点 |
| `越权拒绝` / `refused` | 派单要求越界（代签、代批准、越目录写盘），拒绝并写明越权点 |

## 4. 四条硬规矩

1. **每个产物都要给绝对路径 + SHA256 + 字节数。** 没算过的一律标"未验证"。
2. **不许把"未查"写成"满足"，不许把"模板"写成"已完成"。** 这是回执里最严重的失真。
3. **不代签、不代批准。** 最终签署权永远在人或其明示授权的通道手里；承接方只能出草案/结论。
4. **只读验证与写回执分离。** 核验方读文件、算哈希、出结论；不顺手改被核验的东西。

## 5. 状态机

```
dispatch 落盘
   │  ← patrol.mjs 在这里报「待领」
   ▼
承接方写 receipt  ──►  patrol.mjs 报「已认领」
   │  ← watch.mjs 在这里把你叫醒
   ▼
核验方写 verdict（PASS / HOLD / FAIL，FAIL 必须列打回项）
   │
   ▼
人工/授权通道签署  →  下一单
```

`watch.mjs` 负责发现变化，`patrol.mjs` 负责判断该谁动。两者之间的"该不该动"由本协议定义。

## 6. 核验方的机械核验清单（可直接抄）

- [ ] 必填字段齐全（`task_id` / `executor` / `model_id` / `overall`）
- [ ] `overall` 落在五态枚举内
- [ ] 每个产物都有绝对路径 + SHA256 + 字节数
- [ ] 自己复算一遍哈希，与回执登记值对照（**不采信自报**）
- [ ] 扫"把未查写成满足""把模板写成已完成"的表述
- [ ] 扫"代签 / 代批准 / 代替上级决策"的表述
- [ ] 检查派单白名单之外有没有多余文件落盘

任何一项不过 → `FAIL` 并列打回项；有不确定项 → `HOLD`，不要含糊放过。
