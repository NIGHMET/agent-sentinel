协作闭环：四个动作，两个脚本各管一半

两个代理没有 IPC，唯一的共享面是文件系统。卡点从来不是"会不会干"，而是"什么时候知道对方写了东西"。
1

派单落盘

派单方把 task-001-dispatch-*.md 写进共享交接目录。

watch.mjs → 捕获到 [NEW]
→
2

承接方认领

承接方（人或代理）读到待领清单，开始干活。

patrol.mjs → 报"待领"
→
3

回执落盘

承接方写回 task-001-receipt.md，逐项带证据与哈希。

watch.mjs → 退出即唤醒
→
4

派单方验收

被唤醒后读回执、复算哈希、出结论、派下一单。

patrol.mjs → 待领归零

两个脚本，各答一个问题

  • patrol.mjs — 现在有没有该我干的活？
  • watch.mjs — 活什么时候落盘的？
  • docs/protocol.md — 派单/回执写什么字段

别把「捕获」当「接手」

  • 哨兵只负责捕获差异并落日志（30 秒级）
  • 真正叫醒代理要靠进程退出信号或平台定时任务
  • 对外只能承诺：30 秒内记录 + 会话内≈1 分钟唤醒
